## Summary

Fix the bug where /v1/completions with multiple prompts (batch inference) only returns one set of data.

### Root Cause

In the From<CompletionRequest> for GenerateRequest implementation, all prompts were joined into a single string with `Vec::from(prompt).join("")`. This meant that when the prompt field contained an array of strings, they were concatenated instead of being processed independently.

### Fix

- Replaced From<CompletionRequest> for GenerateRequest with CompletionRequest::into_generate_request(prompt) that takes a single prompt
- respond_one: spawns concurrent tasks via JoinSet, one per prompt, collects results into multiple CompletionChoices with correct index
- respond_stream: spawns concurrent tasks that forward tokens to a shared channel with (index, Token) pairs

### Before vs After

Before: single choice with all prompts joined
After: one choice per prompt with correct index
